解决 macOS 剪贴板历史限制的 Raycast 购物车模式工作流

在日常开发或进行多代码库协同维护时，我们经常需要在本地搭建需求工作区，这就不可避免地要同时克隆（git clone）多个特定分支的仓库。

然而，在这个过程中，macOS 的原生机制带来了一个让人头疼的痛点：macOS 的系统剪贴板不支持历史记录。这意味着如果在 GitLab 或 GitHub UI 上连续点击复制了三个仓库的 git clone 命令，系统剪贴板里最终只会保留最后一次的记录。如果我们试图用自动化脚本批量拉取，系统或者沙盒机制由于无法读取历史剪贴板，最终只能拉取到最后一个项目。

为了在不改变“无脑多次点击复制”这个直觉习惯的前提下突破限制，我们可以利用 Raycast 脚本命令（Script Commands） 构建一个类似“电商购物车”的队列模式。

什么是购物车模式��Queue Pattern）？

顾名思义，“购物车模式”将繁琐的操作拆分为两步：

  1. 加入队列（加购）：将网页上每次复制的命令，追加保存到一个本地的临时隐藏文件（类似于加入购物车）。
  2. 统一结算（清空）：准备就绪后，一键读取这个临时文件里的所有命令，在指定的工作区目录下批量执行，执行完毕后自动销毁文件，防止污染下一次任务。

借助 Raycast 的快捷键和命令别名，我们能让这套动作行云流水。下面是具体的实现步骤。

🛠️ 实现指南

前置准备

  • 已经安装并正在使用 Raycast
  • 了解如何在 Raycast 中创建和运行本地脚本命令 (Script Commands)

Step 1: 创建「加入队列」脚本 (Add)

这个脚本的作用是捕获你当前剪贴板里的单条 git clone 命令，并将它追加到本地隐藏文件 ~/.req_clones.txt 中。

在 Raycast 的 Script Commands 目录下新建一个 Bash 脚本，命名为 add-repo.sh：

#!/bin/bash

# Required parameters:
# @raycast.schemaVersion 1
# @raycast.title 1. add-repo
# @raycast.mode silent

# Optional parameters:
# @raycast.icon 📥

CLIP=$(pbpaste)

# 校验剪贴板内容是否为期望的命令
if [[ "$CLIP" == *"git clone"* ]]; then
  # 追加命令至临时文件
  echo "$CLIP" >> ~/.req_clones.txt
  
  # 提取项目名，用于弹窗提示
  PROJ_NAME=$(echo "$CLIP" | awk -F'/' '{print $NF}' | sed 's/.git//g' | xargs)
  echo "✅ 已加入待拉取队列: $PROJ_NAME"
else
  echo "❌ 剪贴板不是 git clone 命令！"
fi

配置建议：在 Raycast 设置中为该脚本分配一个短别名（Alias），例如 add，这样后续调起会非常快。

Step 2: 创建「结算并清空队列」脚本 (Execute & Clean)

当所有需要的仓库都“加入购物车”后，我们用第二个脚本来“结账”。它会读取队列文件并批量执行 git clone，然后用 IDEA 打开项目，并销毁临时文件。

再次创建一个 Bash 脚本，命名为 init-req.sh：

#!/bin/bash

# Required parameters:
# @raycast.schemaVersion 1
# @raycast.title 2. init-req
# @raycast.mode compact

# Optional parameters:
# @raycast.icon 🚀
# @raycast.argument1 { "type": "text", "placeholder": "需求文件夹名 (如 87090)" }

# 设定你平时存放这些迭代代码的父级工作区目录
WORKSPACE_DIR="/Users/zhao/Public/code/banksteel/迭代"

# 获取命令传入的文件夹名作为新建的工作区
FOLDER_NAME="$1"
TARGET_DIR="$WORKSPACE_DIR/$FOLDER_NAME"

# 检查队列文件是否存在
if [ ! -f ~/.req_clones.txt ]; then
  echo "❌ 还没有添加任何仓库命令！"
  exit 1
fi

mkdir -p "$TARGET_DIR"
cd "$TARGET_DIR" || exit

# 逐行读取临时文件中的 clone 命令并执行
while IFS= read -r line; do
  line=$(echo "$line" | xargs)
  if [[ "$line" == git\ clone* ]]; then
    eval "$line"
  fi
done < ~/.req_clones.txt

# 结算完成，清空购物车
rm ~/.req_clones.txt

# 使用默认编辑器（如 IntelliJ IDEA）打开刚才拉取好的目录
open -a "IntelliJ IDEA" "$TARGET_DIR"
echo "✅ 工作区 $FOLDER_NAME 准备就绪！"

配置建议：给此脚本设置别名，例如 init。由于它带有一个参数框，你在触发时可以直接输入本次需求的编号。

🚀 丝滑的实战体验

完成上述两步配置后，这套自动化的实战体验是这样的：

  1. 网页上点击 Copy (复制第一个项目拉取命令)
  2. 敲击快捷键调起 Raycast -> 输入 add -> 回车 (提示加购成功)
  3. 网页上点击 Copy (复制第二个项目) -> 重复 add 操作 …
  4. 敲击快捷键调起 Raycast -> 输入 init 87090 -> 回车

短短几秒钟，原本需要反复切换窗口、粘贴执行终端的枯燥工作，就被压缩成了指尖无缝衔接的肌肉记忆。这种范式不仅突破了系统剪贴板历史的局限，还完美弥合了我们与前端 GUI 交互以及后端 CLI 批量执行之间的鸿沟。
